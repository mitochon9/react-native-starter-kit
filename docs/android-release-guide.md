## 全体の流れ

```
1. EASでproductionビルド（.aab生成）
       ↓
2. Google Play Consoleでアプリ作成
       ↓
3. ストア掲載情報を入力（説明文、スクリーンショット等）
       ↓
4. .aabファイルをアップロード
       ↓
5. 審査提出
       ↓
6. 審査通過後、公開
```

**所要時間の目安:**
- EASビルド: 15〜30分
- ストア掲載情報入力: 1〜2時間（初回のみ）
- 審査: 数時間〜数日

## 事前準備

### 必要なアカウント

| 項目 | 詳細 |
|-----|------|
| Google Play Developer | 登録料 $25（一回のみ） |
| Expo アカウント | EASビルド用 |

### Google Play Developerアカウント作成

1. https://play.google.com/console/ にアクセス
2. 「新規登録」から開発者アカウントを作成
3. 登録料 $25 を支払い
4. 本人確認を完了

### 必要な素材

| 素材 | サイズ | 備考 |
|-----|-------|------|
| アプリアイコン | 512x512 px | PNG、透過なし |
| フィーチャーグラフィック | 1024x500 px | ストアのヘッダー画像 |
| スクリーンショット | 最低2枚 | 16:9または9:16推奨 |
| 短い説明文 | 80文字以内 | |
| 詳細な説明文 | 4000文字以内 | |

## EASビルド

### 1. ビルドコマンド

```bash
# package.jsonに登録済みのスクリプトを使用
bun run build:android

# または直接実行
eas build --platform android --profile production
```

### 2. ビルド状況の確認

ビルドが開始されると、Expo ダッシュボードのURLが表示されます。

```
See logs: https://expo.dev/accounts/xxxxx/projects/three-year-diary/builds/xxxxx
```

### 3. ビルド完了後

- ビルドが完了すると `.aab` ファイルがダウンロード可能になります
- Expo ダッシュボードから直接ダウンロード
- または `eas build:list` で確認

```bash
# 最新のビルドをダウンロード
eas build:list --platform android
```

### 4. 自動バージョンアップ

`eas.json` の設定により、ビルドごとに `versionCode` が自動でインクリメントされます:

```json
{
  "build": {
    "production": {
      "autoIncrement": true
    }
  }
}
```

## Google Play Console設定

### 1. アプリの作成

1. Google Play Console にログイン
2. 「すべてのアプリ」→「アプリを作成」
3. 以下を入力:

| 項目 | 値 |
|-----|-----|
| アプリ名 | Three Year Diary |
| デフォルトの言語 | 日本語 |
| アプリまたはゲーム | アプリ |
| 無料または有料 | 無料 |

4. デベロッパープログラムポリシーに同意

### 2. ダッシュボードのセットアップ

アプリ作成後、ダッシュボードに「セットアップタスク」が表示されます。
すべてのタスクを完了する必要があります:

- アプリのアクセス権
- 広告の有無
- コンテンツのレーティング
- ターゲットユーザー
- データセーフティ

## ストア掲載情報の入力

### 1. メインのストア掲載情報

「ストアでの表示」→「メインのストア掲載情報」

#### アプリの詳細

```
アプリ名: Three Year Diary
短い説明: 3年間の日記を1画面で振り返れる、シンプルな日記アプリ
詳細な説明:
Three Year Diaryは、同じ日付の日記を3年分並べて表示できるユニークな日記アプリです。

【特徴】
・1年前、2年前の自分と対話するような日記体験
・シンプルで使いやすいインターフェース
・オフライン対応で、いつでもどこでも記録可能
・プライバシーを重視した設計

【こんな方におすすめ】
・日記を習慣にしたい方
・過去の自分を振り返りたい方
・シンプルな日記アプリを探している方
```

#### グラフィック

| 項目 | 要件 |
|-----|------|
| アプリアイコン | 512x512 px, PNG |
| フィーチャーグラフィック | 1024x500 px, PNG/JPG |
| スクリーンショット（スマホ） | 2〜8枚、16:9 or 9:16 |
| スクリーンショット（タブレット） | 任意 |

### 2. コンテンツのレーティング

「ポリシー」→「アプリのコンテンツ」→「コンテンツのレーティング」

質問に回答してレーティングを取得:
- 暴力的なコンテンツ: なし
- 性的コンテンツ: なし
- ユーザー生成コンテンツ: なし（日記はローカル保存のため）

→ 通常「3+」または「全ユーザー対象」のレーティングになります

### 3. データセーフティ

「ポリシー」→「アプリのコンテンツ」→「データセーフティ」

Three Year Diaryの場合（広告なし・課金なしの場合）:

| 質問 | 回答 |
|-----|------|
| データを収集または共有しますか？ | いいえ |
| データの暗号化 | はい（端末内保存） |
| データ削除リクエスト | 対応（アプリ削除で削除） |

## アプリのアップロード

### 1. 内部テスト（推奨）

本番公開前に内部テストで動作確認することを推奨。

1. 「テスト」→「内部テスト」
2. 「新しいリリースを作成」
3. `.aab` ファイルをアップロード
4. リリースノートを記入
5. 「リリースのレビュー」→「公開開始」

テスターを追加:
1. 「テスト」→「内部テスト」→「テスター」タブ
2. メールリストを作成
3. テスターのGoogleアカウントを追加

### 2. 製品版リリース

1. 「リリース」→「製品版」
2. 「新しいリリースを作成」
3. `.aab` ファイルをアップロード
4. リリースノートを記入

```
リリースノート例:
・初回リリース
・3年間の日記を1画面で確認できます
・ダークモード対応
```

5. 「リリースのレビュー」
6. 「製品版として公開開始」

## 審査・公開

### 審査プロセス

1. **審査待ち**: 数時間〜数日
2. **審査中**: Googleによるレビュー
3. **公開準備完了** or **却下**

### 審査で確認されること

- ポリシー違反がないか
- 実際に動作するか
- 説明とアプリの内容が一致しているか
- セキュリティ上の問題がないか

### 却下された場合

1. 却下理由を確認
2. 問題を修正
3. 再提出

よくある却下理由:
- メタデータ（説明文・スクリーンショット）の問題
- 権限の過剰要求
- プライバシーポリシーの不備

## アップデート時の手順

### 1. バージョン更新

`app.json` の `version` を更新（任意）:

```json
{
  "expo": {
    "version": "1.1.0"
  }
}
```

※ `versionCode` はEASが自動でインクリメントします

### 2. ビルド

```bash
bun run build:android
```

### 3. アップロード

1. Google Play Console → 該当アプリ
2. 「リリース」→「製品版」
3. 「新しいリリースを作成」
4. 新しい `.aab` をアップロード
5. リリースノートを記入
6. 公開

## トラブルシューティング

### ビルドが失敗する

```bash
# キャッシュクリアしてビルド
eas build --platform android --profile production --clear-cache
```

### versionCodeが重複している

EASの `appVersionSource: "remote"` 設定により、自動管理されます。
手動で `app.json` の `versionCode` を変更する必要はありません。

### 署名キーの問題

EASが自動で署名キーを管理しています。
キーの確認:

```bash
eas credentials
```
