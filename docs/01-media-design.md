# メディア設計

## 1. コンセプト

### メディア名

**Beyond Vibe** (https://beyond-vibe.com)

### コアメッセージ

> 「Vibeコーディングを否定しない。ただ、死なないコードの書き方を教える」

- Vibeコーディング勢を敵視しない
- 彼らが「次のステップ」に進むための情報を提供
- エンジニアの視点で、AIとの正しい付き合い方を発信

### ターゲット

| 層 | 説明 |
|----|------|
| **メイン** | Vibeコーディングでアプリを作り始めた非エンジニア / 初心者 |
| **サブ** | AI活用に興味があるジュニア〜ミドルエンジニア |

### 市場

- **英語圏メイン**（市場規模重視）
- 日本語は後から追加 or 別運用

### 競合との差別化

| 競合 | 問題点 |
|------|--------|
| 素人向け「AIでアプリ作れました！」系 | 再現性がない、保守の話がない |
| エンジニアの冷笑「Vibeコーディング（笑）」系 | 建設的じゃない |
| **Beyond Vibe** | Vibeコーディングの限界を理解した上で、どう活かすかを教える |

## 2. 技術スタック

### 確定構成

| レイヤー | 技術 | 備考 |
|----------|------|------|
| **Framework** | Next.js (App Router) | |
| **Styling** | Tailwind CSS | |
| **Content** | MDX | ローカル管理 |
| **Hosting** | Cloudflare Pages | OpenNext (`@opennextjs/cloudflare`) 使用 |
| **Domain** | beyond-vibe.com | Cloudflare で取得済み |

### 将来の拡張（必要になったら）

| 機能 | 技術 | タイミング |
|------|------|------------|
| API | Hono (Cloudflare Workers) | 会員機能等が必要になったら |
| DB | Turso | 同上 |
| ニュースレター | Buttondown or Resend | 読者が増えたら |
| コメント | giscus (GitHub Discussions) | 記事増えたら |

### 設計方針

- **YAGNIを徹底**：最初は完全静的サイト（SSG）
- バックエンド/DBは本当に必要になるまで追加しない
- 外部サービスで済むものは外部サービスを使う
